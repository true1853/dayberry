# Дайбери

Площадка бартерного обмена: люди меняются вещами и услугами без денег.
Разница в стоимости добирается внутренними баллами, а сделку держит эскроу.

Прод: **dayberry.ru** · Разработка: студия ПРИЗМАТИКА · ООО «ПРИЗМАТИКА»

Состояние на 13 августа 2026: 18 пользователей, 91 активное объявление,
11 сделок, 22 переписки. Запуск идёт по Владимирской области.

## Продукт

### Зачем всё это

Прямой бартер почти никогда не сходится: вам нужен велосипед, у соседа он
есть, но ему ваш монитор не нужен. Это «двойное совпадение желаний» —
причина, по которой предыдущие площадки обмена умирали с низкой конверсией.

Дайбери развязывает совпадение двумя способами: **баллами** (отдал вещь →
получил баллы → потратил у другого человека) и **цепочками** (система сама
находит круг из трёх участников, где каждый получает нужное).

### Баллы

Внутренняя единица, 1 балл = 1 ₽ — просто чтобы людям была понятна шкала.
Баллы **нельзя вывести**: они существуют, чтобы уравнивать обмены. Начисляются
за состоявшийся обмен; пополнение кошелька работает в тестовом режиме — код
просто увеличивает баланс, платёжного провайдера за ним нет.

### Как проходит сделка

1. Автор размещает лот: фото, название, состояние, что хочет взамен.
   Категорию и коридор оценки подсказывает ИИ.
2. Второй участник предлагает обмен: свой лот плюс доплата баллами, если
   его вещь дешевле. Форма показывает, сколько не хватает до равноценного.
3. Доплата **замораживается**: списывается с баланса, но партнёру не уходит.
4. Обе стороны подтверждают получение — эскроу размораживается, баллы уходят
   владельцу лота, у обоих растёт счётчик сделок, открывается оценка партнёра.
5. Если что-то пошло не так — **спор**: сделка замирает, баллы остаются
   замороженными, решение принимает администратор (вернуть или засчитать).

Отмена возможна, пока никто не подтвердил получение. После первого
подтверждения выход только через спор — иначе баллы зависали бы навсегда.

### Цепочки

Движок ищет циклы в ориентированном графе участников: ребро «А → Б» значит
«Б возьмёт что-то из вещей А». Цикл из трёх и есть цепочка.

- **circle** — круг замкнут желанием, каждый получает вещь;
- **credit** — круг замыкается баллами: последний ничего не отдаёт, а платит.

Ищем по региону участника (внутри одного города плотности не хватает), а через
границу региона пускаем только то, что оказывается удалённо: дизайн, реклама,
консультации. Человек может переключить поиск на «любой город» — тогда
география снимается совсем.

Кандидаты никого не беспокоят, пока кто-то не нажмёт «я в деле»; после этого
остальным уходят уведомления и включается суточный таймер.

### Подбор («умный мэтчинг»)

Сравнивает тексты через эмбеддинги (`qwen3-embedding-4b` через routerai.ru),
косинус калибруется под шкалу 0..1, к похожести примешивается близость цен.
При отказе провайдера — откат на пересечение слов, пороги для этого режима
свои. Учитываются **все** лоты человека и его вишлист, а не первый попавшийся.

### Модерация

Постмодерация по жалобам: премодерации нет намеренно — при полусотне
объявлений в сутки сплошная проверка съедает больше, чем спасает.

- Жалоба на объявление с причиной; несколько жалоб на один лот сводятся
  в одну задачу.
- **Скрытие модератором** — отдельный статус лота: автор его не отменит,
  в отличие от собственного архива.
- **Мягкая блокировка**: вход и переписка сохраняются (чтобы человек закрыл
  начатое), но объявления уходят из ленты, новые размещать и открывать сделки
  нельзя. Активные сделки заблокированного автоматически уходят в спор.
- Правила сервиса со списком запрещённого — на них ссылается и модерация,
  и форма жалобы.

### Уведомления

Единая точка — `lib/notify.js`: запись в `Notification` (колокольчик внутри
приложения) плюс web-push на устройства, если человек его включил.

Поводы: сообщение в чате, предложение обмена, подтверждение получения,
завершение обмена, отмена, возврат баллов, новый отзыв, все события цепочек,
спор и его решение, модерация, рассылка администратора.

### Приложение на телефоне

PWA: манифест, иконки (обычные и maskable), сервис-воркер с офлайн-страницей
и приёмом push, своё предложение «установить на главный экран» (на iOS —
текстовая инструкция, системного приглашения там нет).

Обновление данных: открытая переписка опрашивает сервер раз в 4 секунды,
список чатов — 20, колокольчик — 45; на остальных экранах работает жест
«потянуть вниз».

### Инструменты администратора

Доступ по списку почт в `ADMIN_EMAILS`, проверка на сервере. В настройках:

- **Жалобы** — очередь модерации;
- **Споры** — разбор сделок, два исхода (вернуть баллы / засчитать обмен);
- **Сброс пароля** — заявки от тех, кто не может войти; выдача временного
  пароля (показывается один раз, в базе только хеш);
- **Рассылка** — уведомление всем или только тем, у кого есть объявления.

## Устройство

### Стек

Next.js 15 (App Router, server actions) · React 19 · Prisma 6 + SQLite (WAL) ·
sharp для картинок · web-push · jose для сессий · Docker.

Всё живёт одним процессом Node на одном сервере; распределённых хранилищ нет
и не нужно — нагрузка соответствующая.

### Структура

```
app/            входная точка Next, layout, Метрика, отдача /uploads
src/            интерфейс: экраны, дизайн-система, роутер по hash
src/server/     server actions — вся серверная логика приложения
lib/            движки: ai.js (оценка, эмбеддинги), chains.js (цепочки),
                notify.js, push.js, storage.js (фото), auth.js, prisma.js
prisma/         схема (17 моделей)
scripts/        миграции фото и чатов, снимок базы для бэкапа
public/         иконки, манифест, сервис-воркер, офлайн-страница
```

### Данные

`User` · `Lot` · `LotPhoto` · `Favorite` · `Deal` · `Transaction` ·
`Chat` · `ChatMember` · `Message` · `Chain` · `ChainStep` · `Review` ·
`Notification` · `PushSubscription` · `Report` · `PasswordReset` · `AiCache`

Статусы лота: `active` · `archived` (спрятал автор) · `in_chain` (занят
цепочкой) · `hidden` (скрыл модератор).

### Решения, которые стоит знать

**Порядок ленты — дата размещения.** Первым ключом когда-то стоял
`sortOrder` «ручного закрепления», но выставлять его было некому: у всех
объявлений там ноль. Колонка осталась в схеме (её удаление потребовало бы
разрушающего `db push` при старте), но в запросах не участвует.

**Фотографии — на диске, не в базе.** Имя файла — хеш содержимого, поэтому
одинаковые снимки не дублируются. Хранятся в WebP двух размеров (1600 и 640
пикселей), отдаются с иммутабельным кэшем через `app/uploads/[file]`.

**Гонки закрыты условными обновлениями.** Списание баллов, подтверждение
получения и отмена сделки идут через `updateMany` с проверкой в `where`, а не
по ранее прочитанному значению: два параллельных запроса иначе проходят одну
проверку дважды.

**Загрузка приложения — три обращения к серверу вместо десяти.** Server
actions сериализуются по одному клиенту, поэтому стартовые данные собраны
в `bootstrapAction` и `loadAuthedDataAction`.

**Экспортировать из `'use server'` можно только асинхронные функции.**
Константа там валит приложение в рантайме, а сборка это пропускает — поэтому
списки вроде причин жалоб лежат отдельными модулями.

## Локальный запуск

```bash
npm ci
printf 'DATABASE_URL="file:./dev.db"\nAUTH_SECRET="dev-secret"\n' > .env
npx prisma db push
npm run dev
```

ИИ-функции без `AI_API_KEY` не падают: оценка отдаёт эвристику, подбор и
цепочки переходят на пересечение слов.

## Переменные окружения

| Переменная | Зачем |
|---|---|
| `DATABASE_URL` | путь к SQLite; на проде `file:/app/data/dayberry.db` |
| `AUTH_SECRET` | подпись сессий, приложение не стартует без него |
| `ADMIN_EMAILS` | почты администраторов через запятую |
| `AI_API_KEY`, `AI_BASE_URL`, `AI_MODEL`, `AI_EMBED_MODEL` | оценка и эмбеддинги |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | web-push |
| `UPLOAD_DIR` | папка с фотографиями; по умолчанию `data/uploads` рядом с приложением |
| `VK_CLIENT_SECRET`, `NEXT_PUBLIC_VK_CLIENT_ID` | вход через VK |
| `APP_URL` | абсолютные ссылки в OAuth |

## Деплой

Сервер 185.180.251.60, порт SSH 17236, пользователь `srvadm`,
каталог `~/apps/dayberry`.

```bash
git pull origin main && docker compose build --no-cache && docker compose up -d
```

При старте контейнера выполняется `prisma db push` (создаёт недостающие
таблицы и колонки, данные не удаляет) и миграции фото и чатов — они
идемпотентны.

**Данные на проде не трогать.** Никаких `deleteMany` «для очистки»: там живые
аккаунты, переписки и замороженные баллы. Для проверок заводить отдельных
тестовых пользователей и удалять только их, по конкретным адресам.

## Бэкапы

Ночью в 3:55 по крону: `~/backups/dayberry/backup_dayberry.sh`.

Снимок базы делает `VACUUM INTO` (копировать файл на ходу нельзя — WAL),
фотографии уезжают отдельным архивом. Хранится 14 копий базы и 7 архивов фото.

Восстановление:

```bash
gunzip -c ~/backups/dayberry/dayberry_ДАТА.db.gz > /tmp/restore.db
docker cp /tmp/restore.db dayberry:/app/data/dayberry.db
docker restart dayberry
```

## Аналитика

Яндекс.Метрика (счётчик 111543083). Приложение — SPA на hash-роутере, поэтому
переходы между экранами отправляются вручную, иначе в отчётах был бы один
просмотр на визит. Переписка и поля ввода закрыты от вебвизора классами
`ym-hide-content` и `ym-disable-keys`. Счётчик работает только на боевом
домене — стенды статистику не портят.

Цели: `auth`, `lot_created`, `deal_created`, `deal_done` — их нужно создать
в интерфейсе Метрики как JavaScript-события, код уже отправляет.
